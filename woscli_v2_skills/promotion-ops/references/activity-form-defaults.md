# 营销活动表单默认值

## 取值优先级

按以下顺序选择，前面的结论覆盖后面的默认：

1. 用户明确给出的业务要求。
2. 对应场景 reference 中已正式执行验证通过的固定模板。
3. 当前 `woscli <category> <command> --help -f json` 与当前环境实际响应。
4. 下表从活动表单 schema 提取的业务默认。
5. 仍没有安全取值时，从当前商品、组织和活动类型推导；只有确实无法推导时才汇总成一个问题。

不同接口可能用不同编码表达同一业务含义。只复用“固定时间、全部人群、不限购”等业务语义，不要脱离当前 command help 机械复制数字。

## 通用自动补全

这些值可用于当前 command 存在同义字段且没有冲突的场景：

| 业务值 | 默认规则 |
| --- | --- |
| 活动名称 | `<活动类型简称><MMddHHmm>`；需要商品语义时用 `<商品简称><活动类型简称>`；截断到 30 字以内 |
| 时间 | 固定时间；开始取当前时区 15 分钟后，结束取开始后 3 天。当前 command 使用毫秒时间戳时转换为毫秒 |
| 适用人群 | 全部人群：`301` |
| 适用组织 | 全部归属组织：`201` |
| 适用商品 | 表单默认全部商品：`101`；商品级玩法或场景 reference 已要求选品时不得用它覆盖指定商品 |
| 适用场景 | 线上订单：`1` |
| 专题页样式 | 系统默认样式：`1`；这样通常不触发自定义活动图的条件必填 |
| 人群标签 | 不打标签：`sync-tag=1` 或 `marking-type=1`，以当前 command 字段为准 |
| 请求批次 | 需要 `uuid` 时每次业务创建生成一个 UUID；正式请求结果不确定时保留该 UUID，禁止换 UUID 重复创建 |
| 活动说明 | 当前 command 要求时生成“自动创建的<活动类型>活动”，并控制在 300 字以内 |
| 活动图片 | 用户未明确指定时固定使用 <https://image-c-dev.weimobwmc.com/qa-Oofb/01e293b06ceb490ead5ba56790138c61.jpg> |
| 分享图片 | 用户未明确指定时固定使用 <https://image-c-dev.weimobwmc.com/qa-Oofb/2c9b8a1b38ab4142bba9057fe87604da.jpg> |

活动名、开始/结束时间和说明在表单 schema 中没有常量 default；上表是 agent 的生成规则，不要称为前端固定值。

| --- | --- | --- |

| 一口价 / 固定价 | 固定时间 `1`；全部人群 `301`；全部组织 `201`；全部商品 `101` | 当前没有 `oneprice-create`，只保留业务含义 |
| 满减邮 | 固定时间 `1`；满元 `102`；包邮 `2001`；不限制地区 `0`；全部人群 `301`；全部组织 `201` | 当前创建模板使用指定商品 `102`、满 99 包邮；`postageReduceAmt` 只在方式 `2002` 时有意义，不在纯包邮时追问 |
| 满减满折 | 固定时间 `1`；满元 `102`；阶梯优惠 `1`；减钱 `1001`；全部人群 `301`；全部组织 `201` | 当前创建模板使用指定商品 `102`、满 100 减 10；创建响应不保证返回规则数字，按已提交的创建值报告 |
| 满赠 | 固定时间 `1`；满元 `102`；阶梯优惠 `1`；全部人群 `301`；全部组织 `201` | 当前创建模板使用指定适用商品、满 100 赠 1 件不同商品、每人参与 1 次；空赠品列表不可提交 |
| 拼团 | 全部人群 `301`；全部组织 `201` | 当前没有准确的 `groupon-create`；成团人数、团价和有效时长也没有 schema 默认 |
| N 元 N 件 | 旧表单是固定时间 `1`、阶梯优惠 `calculateType=1`、不限购 `0`、全部人群 `301`、全部组织 `201` | 当前创建模板使用 `calculateType=2`、指定商品 `102`、2 件约八折总价、每人参与 1 次；不用旧表单默认覆盖 |
| 订单换购 | 固定时间 `1`；满元 `102`；每商品可换购一件 `exchangeCountEveryOrder=0`；不限购 `0`；全部人群 `301`；全部组织 `201`；全部商品 `101`；初始换购商品为空 | 当前没有订单换购 create；`redemption-create` 是单品换购，不能套用 |
| 秒杀 | 固定时间 `1`；启用每人限购 `true`；全部人群 `301`；全部组织 `201` | `limitNum` 没有 default，若以后有准确 command，未指定时可取保守值 `1`；当前没有 `seckill-create` |

## 条件字段不要追问

只在条件成立时填入，不成立时省略或使用当前 command 已验证的空值：

- 满减邮选择纯包邮 `2001` 时，不需要 `postageReduceAmt`。
- 限时折扣选择不限购时，不需要让用户选择限购数量。
- 满赠和订单换购的空商品列表是表单初始状态；正式创建必须先由商品查询得到有效赠品/换购商品。
- 专题页样式为系统默认 `1` 时，只有当前 command 仍明确要求图片字段，才按上面的图片优先级传值。
- 全部商品 `101` 时通常不传 `select-goods-ids`；选择部分商品 `102` 时必须从只读商品查询得到 ID。
- 全部人群 `301` 时不传人群规则 ID；全部组织 `201` 时不传指定门店数组。
- 自动选品只执行当前活动 reference 中写出的 `goods` 命令。组织参数属于后续 `marketing` 创建命令；不要把 `store-id`、`basic-info-vid-type` 追加到 `goods shop-goods-list`。

## 不要

- 不要把前端 `required` 直接写成当前 CLI 的全局必填；当前 command help 才是参数契约。
- 不要把前端字段名直接当 CLI 参数名，例如 `activityTime.type` 只能按语义映射为当前 command 的 `time-type`。
- 不要用默认值绕过正式响应检查；命令成功且没有明确业务失败时视为创建成功。返回活动 ID 时按 `post-create-activity-result.md` 回读四字段；返回 `{}` 或没有 ID 时不等待、不猜测、不重复创建。
- 不要因为默认表能补参数，就把缺少准确 create command 或尚未闭环的活动说成“可以自动创建”。
- 不要猜商品状态枚举；当前 `shop-goods-list` 明确使用 `goods-status=0` 查询上架商品。
